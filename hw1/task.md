### **Домашнее задание: Развертывание пользовательского веб-приложения с логированием и балансировкой**

1. **Разработать пользовательское веб-приложение**
    - Приложение должно быть написано на любом языке (например, Python/Flask, Node.js/Express, Java/Spring Boot).
    - API должно включать следующие эндпоинты:
        - `GET /` — возвращает строку `"Welcome to the custom app"`
        - `GET /status` — возвращает JSON `{"status": "ok"}`
        - `POST /log` — принимает JSON `{"message": "some log"}` и записывает его в локальный лог-файл `/app/logs/app.log`
        - `GET /logs` — возвращает содержимое файла `/app/logs/app.log`
    - Логи приложения должны сохраняться в `/app/logs/app.log`.

2. **Развернуть приложение в Kubernetes в виде Pod**
    - Написать Dockerfile для сборки образа приложения.
    - Создать Pod, который запускает контейнер с этим приложением.
    - Монтировать `emptyDir` volume в `/app/logs`, чтобы логи сохранялись во время работы пода.

3. **Настроить Deployment для масштабирования**
    - Создать Deployment с 3 репликами.
    - Убедиться, что при обновлении приложения новые поды получают последнюю версию кода.
    - Проверить, что логи сохраняются в `emptyDir` даже после перезапуска контейнера.

4. **Настроить Service для балансировки нагрузки**
    - Создать Service (ClusterIP), который раздает трафик между подами.
    - Проверить работу API через `curl` или `kubectl port-forward`.

5. **Развернуть DaemonSet для сбора логов**
    - Создать DaemonSet с `log-agent`, который:
        - Читает `/app/logs/app.log` на каждом узле (используя `hostPath`).
        - Отправляет логи на удаленный сервер или сохраняет их в файл на узле.
    - Проверить, что логи собираются корректно.

6. **Проверить работоспособность системы**
    - Убедиться, что балансировка запросов работает (`curl http://custom-service/logs`).
    - Проверить, что DaemonSet собирает логи с каждого узла (`kubectl logs log-agent-pod`).
    - Удалить один из подов и убедиться, что новые поды продолжают логирование.
    - Проверить, что `POST /log` корректно записывает данные и они доступны через `GET /logs`.
